STEP 01 / ไม่ต้องติดตั้งอะไร

ทดลองเว็บไซต์ก่อน

  1. เปิด เว็บไซต์ SkillTrust ด้วย Chrome หรือ Edge บนคอมพิวเตอร์
  2. เห็นป้าย Demo mode / พื้นที่ทดลอง หมายความว่ากำลังใช้ข้อมูลจำลอง ไม่ได้ใช้เงินจริงและไม่ใช่ธุรกรรมบน Blockchain
  3. ไปที่ ตรวจสอบใบรับรอง แล้วกดปุ่มลองตรวจสอบตัวอย่าง จะพบใบรับรองที่มีผลใช้งาน
  4. กด เชื่อมต่อ Wallet ด้านขวาบน ใน Demo จะเชื่อมบัญชีจำลอง 0x1111…1111 ไม่เปิด MetaMask
  5. ไปที่ จัดการระบบ ลองแท็บหลักสูตร ออกใบรับรอง ทะเบียนใบรับรอง และจัดการสิทธิ์
  6. ลองออกใบรับรองด้วยรหัสใหม่ เช่น ST-DEMO-001 เลือกหลักสูตร ใส่ชื่อสมมติ และใช้ Wallet จำลองที่มีให้
  7. ออกสำเร็จ กด ดาวน์โหลด JSON และ พิมพ์ / PDF เพื่อดูผล
Demo เก็บข้อมูลในเบราว์เซอร์เครื่องนั้น คนอื่นเปิดเว็บจะเห็นข้อมูลของตนเอง ไม่มีการแชร์ข้อมูล Demo ข้ามเครื่อง อย่าใช้ชื่อจริงในเครื่องสาธารณะ

STEP 02 / ทำบนคอมพิวเตอร์จะสะดวกที่สุด

ติดตั้งและสร้าง MetaMask

  1. เปิดเว็บทางการ metamask.io/download แล้วติดตั้งส่วนขยายสำหรับเบราว์เซอร์ที่ใช้งาน
  2. เปิด MetaMask จากไอคอน Extensions ของเบราว์เซอร์ หากต้องการให้เห็นตลอดให้กดปักหมุด
  3. เลือกสร้าง Wallet ใหม่ หากมี Wallet อยู่แล้วใช้บัญชีเดิมได้
  4. ตั้งรหัสผ่านในอุปกรณ์ และทำขั้นตอนสำรอง Secret Recovery Phrase ของ MetaMask ให้ครบ
  5. เมื่อเข้าหน้า Wallet ได้ ให้ดูชื่อบัญชี เช่น Account 1 และ Address ที่ขึ้นต้นด้วย 0x
  6. กดชื่อ/Address เพื่อคัดลอก Address ของ Wallet เก็บไว้ใช้เป็นบัญชีผู้ดูแล
เก็บ Secret Recovery Phrase และ Private Key ไว้กับตัวเอง ไม่ต้องกรอกลงเว็บไซต์ SkillTrust, GitHub, Remix หรือส่งมาในแชต การเชื่อมต่อและยืนยันธุรกรรมทำผ่านหน้าต่าง MetaMask เท่านั้น

Address มีสองชนิด อย่าสับสน

ชนิดได้มาจากไหนใช้ทำอะไร
Wallet Addressบัญชีใน MetaMaskใช้รับ ETH ทดสอบ ระบุผู้รับใบรับรอง และให้สิทธิ์ Admin/Issuer
Contract Addressได้หลัง deploy ใน Remix สำเร็จใส่ในหน้าตั้งค่าเว็บไซต์ เพื่อบอกให้เว็บอ่านทะเบียนไหน

ทั้งสองขึ้นต้น 0x และยาว 42 ตัวอักษรเหมือนกัน แต่ทำหน้าที่ต่างกัน

STEP 03 / เครือข่ายทดสอบ

เปิด Sepolia และเติม ETH ทดสอบ

  1. ใน MetaMask เปิดตัวเลือกเครือข่ายด้านบน มองหา Show test networks / แสดงเครือข่ายทดสอบ แล้วเปิด หากไม่พบ ให้ดูใน Settings → Advanced หรือเมนูเครือข่ายของเวอร์ชันที่ใช้อยู่
  2. เลือก Sepolia หรือ Sepolia test network ให้แน่ใจว่าไม่ใช่ Ethereum Mainnet
  3. เปิด faucet เช่น Google Cloud Sepolia Faucet หรือ Alchemy Sepolia Faucet
  4. ทำตามขั้นตอนของ faucet อาจต้องเข้าสู่ระบบหรือผ่านเงื่อนไขของผู้ให้บริการ
  5. วาง Wallet Address จาก MetaMask แล้วขอรับ Sepolia ETH
  6. กลับ MetaMask รอให้ยอด SepoliaETH หรือ ETH บน Sepolia เพิ่มขึ้น ยอดต้องมากกว่า 0 ก่อน deploy
Sepolia ETH ใช้จ่ายค่า Gas บนเครือข่ายทดสอบ ไม่ต้องซื้อ ETH จริงสำหรับโครงการนี้ หาก faucet จำกัดจำนวนหรือให้ไม่ได้ ให้รอหรือเลือกผู้ให้บริการอื่น

Chain ID ของ Sepolia คือ 11155111 ส่วน Ethereum Mainnet คือ 1 อย่าส่งธุรกรรมของงานนี้บน Mainnet

STEP 04 / นำไฟล์ Solidity เข้า IDE

เปิด Remix และสร้างไฟล์ Contract

  1. เปิด remix.ethereum.org ในเบราว์เซอร์เดียวกับที่ติดตั้ง MetaMask
  2. ถ้ามีหน้าต่างต้อนรับ ให้ผ่านหรือปิดเพื่อเข้าสู่ workspace
  3. ที่แถบซ้าย เลือก File Explorer ซึ่งเป็นไอคอนไฟล์
  4. เปิดโฟลเดอร์ contracts หรือสร้างโฟลเดอร์ใหม่ชื่อนี้
  5. สร้างไฟล์ใหม่ชื่อ SkillTrustRegistry.sol ชื่อและนามสกุลต้องตรง
  6. เปิด ไฟล์ Solidity ใน GitHub แล้วกด Raw หรือปุ่ม Copy raw file เพื่อคัดลอกโค้ดทั้งหมด
  7. กลับ Remix วางโค้ดทั้งหมดในไฟล์ที่สร้าง แล้วกด Ctrl+S (Mac ใช้ Cmd+S)
Remix IDE ที่ใช้ในงานนี้เป็นเครื่องมือเขียนและ deploy Solidity ไม่ใช่ Remix framework สำหรับสร้างเว็บ ไม่ต้องติดตั้ง Remix ลงในเครื่อง

STEP 05 / ค่าที่แนะนำตรงกับโครงการ

ตั้งค่า Compiler แล้ว Compile

  1. คลิกไอคอน Solidity Compiler ที่แถบซ้ายของ Remix
  2. Compiler เลือก 0.8.30 (โค้ดรองรับ 0.8.24 ขึ้นไป แต่ใช้ 0.8.30 ให้ตรงชุดทดสอบ)
  3. เปิด Advanced Configurations
  4. ตั้ง EVM Version = shanghai
  5. เปิด Enable optimization และกำหนด Runs = 200
  6. ตรวจว่าไฟล์ที่เปิดคือ SkillTrustRegistry.sol แล้วกด Compile SkillTrustRegistry.sol
  7. ถ้าไม่พบ error และเห็น contract SkillTrustRegistry แสดงว่า compile ผ่าน
ค่าตั้งใช้ค่า
Compiler0.8.30
LanguageSolidity
EVM Versionshanghai
OptimizerEnabled, 200 runs
ContractSkillTrustRegistry

หากมี error สีแดง ให้ตรวจว่าคัดลอกโค้ดครบตั้งแต่ // SPDX-License-Identifier จนถึงวงเล็บปิดท้าย และเลือก Compiler ถูกเวอร์ชัน

STEP 06 / ลงนามด้วย Wallet ของคุณ

Deploy Contract บน Sepolia

  1. ใน MetaMask ตรวจว่าเลือก Sepolia และมี ETH ทดสอบ
  2. ใน Remix เปิด Deploy & Run Transactions จากแถบซ้าย
  3. ตรง Environment เลือกตัวเลือกที่เชื่อม browser Wallet เช่น Injected Provider - MetaMask, Browser Extension หรือ MetaMask ตามเวอร์ชันของ Remix
  4. MetaMask จะขอเชื่อมเว็บไซต์ Remix เลือกบัญชีที่จะเป็นผู้ดูแล แล้วกด Connect
  5. ตรวจ Network ของ Remix/MetaMask ว่าเป็น Sepolia (11155111) และ Account ตรงกับ Wallet ที่ต้องการ
  6. เลือก Contract เป็น SkillTrustRegistry - contracts/SkillTrustRegistry.sol
  7. ช่อง Value = 0 ไม่ต้องส่ง ETH เข้า contract โดยตรง ส่วนค่าธรรมเนียม Gas จะชำระจาก Wallet แยกต่างหาก
  8. constructor ไม่มี argument ไม่ต้องกรอกอะไรเพิ่ม กด Deploy
  9. ตรวจรายละเอียดในหน้าต่าง MetaMask แล้วกด Confirm
  10. รอธุรกรรมสำเร็จ ใน Remix จะมีรายการใต้ Deployed Contracts ชื่อประมาณ SKILLTRUSTREGISTRY AT 0x…
  11. กดปุ่ม Copy ข้าง Address ของ deployed contract เก็บ Contract Address ไว้
  12. ตรวจสอบเพิ่มได้ที่ sepolia.etherscan.io โดยค้นหา Address ที่ได้
อย่าเลือก Remix VM หากต้องการให้เว็บไซต์ใช้งานได้จริง Remix VM เป็น Blockchain จำลองภายใน IDE เว็บที่เชื่อม Sepolia จะอ่าน Contract ใน VM ไม่พบ การ deploy สำหรับเว็บนี้ต้องผ่าน MetaMask บน Sepolia

ตรวจสิทธิ์ Owner ใน Remix

ขยาย deployed contract แล้วกดปุ่มอ่าน owner ควรได้ Wallet Address ของผู้ deploy ลองใส่ Wallet Address เดิมใน admins แล้วกดอ่าน ควรได้ true การอ่านข้อมูลไม่เสียค่า Gas

Owner เริ่มต้นเป็น Admin ด้วย จึงสร้างหลักสูตร ออกใบรับรอง และจัดการสิทธิ์ได้ทันที อย่า deploy ซ้ำทุกครั้งที่เปิด Remix เพราะแต่ละครั้งจะได้ทะเบียนและ Address ใหม่

STEP 07 / เชื่อมส่วนหน้ากับส่วนหลังบ้าน

นำ Contract Address มาใช้บนเว็บ

  1. เปิด SkillTrust → ตั้งค่าการเชื่อมต่อ
  2. เปลี่ยนโหมดจาก Demo เป็น Ethereum Sepolia — Smart Contract จริง
  3. วาง Contract Address ที่ได้จาก Remix ช่องนี้ไม่ใช่ Wallet Address
  4. ใช้ RPC URL เริ่มต้น https://ethereum-sepolia-rpc.publicnode.com ได้ หรือเปลี่ยนเป็น HTTPS RPC ของ Sepolia ที่เข้าถึงจาก browser ได้ ห้ามใส่ key ลับ
  5. กด บันทึกและเชื่อมต่อ ป้ายด้านบนควรเป็น Sepolia Testnet ไม่มีแถบพื้นที่ทดลอง
  6. Contract ใหม่ยังไม่มีหลักสูตรหรือใบรับรอง ตัวเลขเริ่มที่ 0 ถือว่าปกติ
  7. กด เชื่อมต่อ Wallet แล้วอนุญาต MetaMask บนบัญชีเดียวกับที่ deploy
  8. ไปที่ จัดการระบบ ควรเห็นบทบาท Contract Owner
ค่าที่กรอกในหน้าเว็บเก็บเฉพาะเบราว์เซอร์นี้ หากต้องการให้เพื่อนหรือผู้ตรวจสอบเปิดเว็บแล้วอ่าน Sepolia ได้ทันที ต้องตั้งค่า public/config.json ตามด้านล่างด้วย

ตั้ง Contract กลางสำหรับผู้เข้าชมทุกคน

  1. เข้า repository บน GitHub แล้วเปิด public/config.json
  2. กดไอคอนดินสอ Edit
  3. เปลี่ยน "mode": "demo" เป็น "mode": "sepolia"
  4. ใส่ Contract Address จริงใน contractAddress โดยคง Chain ID และ RPC ไว้
  5. กด Commit changes ลง branch main
  6. รอ GitHub Actions เป็นสีเขียว แล้วเปิดเว็บด้วยหน้าต่าง Incognito เพื่อตรวจว่าค่าเริ่มต้นเป็น Sepolia
{
  "mode": "sepolia",
  "chainId": 11155111,
  "contractAddress": "วาง_Contract_Address_จริงของคุณที่นี่",
  "rpcUrl": "https://ethereum-sepolia-rpc.publicnode.com"
}

บรรทัด contractAddress ข้างบนเป็นข้อความอธิบาย ต้องแทนด้วย Address จริงที่ขึ้นต้น 0x และยาว 42 ตัวอักษร

เครื่องที่เคยตั้งค่าในหน้าเว็บมาก่อนจะใช้ค่าของเครื่องนั้นก่อน config กลาง ให้บันทึกหน้า Settings ให้ตรงกันอีกครั้ง หรือทดสอบใน Incognito

STEP 08 / ใช้บัญชี Owner หรือ Admin

สร้างหลักสูตร

  1. เชื่อม Wallet ผู้ deploy แล้วไป จัดการระบบ → หลักสูตร
  2. กรอกตัวอย่าง: รหัส AI-101, ชื่อ AI & Machine Learning Essentials, รายละเอียด อบรมพื้นฐาน AI และ Machine Learning
  3. รหัสใช้ตัวอักษรภาษาอังกฤษ ตัวเลข และขีดกลาง ระบบแปลงเป็นตัวใหญ่ ห้ามใช้รหัสหลักสูตรซ้ำ
  4. กด สร้างหลักสูตร และยืนยันใน MetaMask
  5. รอธุรกรรมสำเร็จ การ์ดหลักสูตรจะปรากฏในรายการและเลือกได้ตอนออกใบรับรอง

ปุ่ม ปิดรับการออกใบรับรอง ป้องกันการออกใบใหม่ในหลักสูตรนั้น ใบเดิมยังตรวจสอบได้ เปิดหลักสูตรกลับได้ภายหลัง

ชื่อและรายละเอียดหลักสูตรเป็นข้อมูลสาธารณะบน Blockchain อย่าใส่ชื่อผู้เรียน เลขบัตรประชาชน เบอร์โทร หรือข้อมูลส่วนตัวในช่องเหล่านี้

STEP 09 / ใช้บัญชี Admin หรือ Issuer

ออกใบรับรองและส่งให้ผู้รับ

  1. ไป จัดการระบบ → ออกใบรับรอง
  2. รหัสใบรับรอง: ใส่รหัสใหม่ เช่น ST-2026-0001 รองรับ A–Z, 0–9 และขีดกลาง ความยาว 3–64 ตัวอักษร ห้ามใช้ซ้ำ แม้ใบเดิมถูกเพิกถอน
  3. วันที่ออก: เลือกวันที่จริง ไม่สามารถออกวันที่ในอนาคต
  4. หลักสูตร: เลือกหลักสูตรที่สร้างและเปิดใช้งานอยู่
  5. ชื่อ–นามสกุล: ใส่ชื่อผู้รับตามต้องการ ชื่อนี้จะอยู่ใน JSON และเอกสาร ไม่ส่งขึ้น Blockchain
  6. Wallet Address ของผู้รับ: ใส่ Wallet ผู้เรียนที่ขึ้นต้น 0x ให้ถูกต้อง หากทดสอบคนเดียวใช้ Wallet ของตัวเองได้
  7. PDF ต้นฉบับ (ไม่บังคับ): หากมี PDF อยู่แล้วและต้องการตรวจว่าถูกแก้ไขหรือไม่ ให้แนบก่อนออกใบรับรอง ระบบคำนวณ SHA-256 ในเครื่อง ขนาดไม่เกิน 20 MB ไม่อัปโหลดไฟล์ขึ้น Blockchain
  8. กด ออกใบรับรอง ตรวจรายละเอียดธุรกรรมใน MetaMask และกด Confirm
  9. รอจนแสดงใบรับรอง แล้วกด ดาวน์โหลด JSON ชื่อไฟล์ลงท้าย .skilltrust.json
  10. กด พิมพ์ / PDF ในหน้าต่างพิมพ์ เลือก Destination เป็น Save as PDF / บันทึกเป็น PDF ใช้กระดาษ A4 แนวนอน ปิด Headers and footers หากเบราว์เซอร์เพิ่ม URL/วันที่บนกระดาษ
  11. กด QR Code เพื่อดาวน์โหลดภาพ QR หรือ คัดลอกลิงก์ เพื่อแชร์หน้าตรวจสถานะ
  12. ส่งไฟล์ JSON และ PDF ให้ผู้รับผ่านช่องทางส่วนตัว อย่า commit เอกสารส่วนตัวเข้า GitHub สาธารณะ
สำรอง JSON ทันที: ชื่อและ nonce ไม่ได้อยู่บน Blockchain หากล้างเบราว์เซอร์โดยไม่ได้สำรอง JSON จะกู้รายละเอียดส่วนตัวจาก Hash ไม่ได้ ระบบนี้ไม่มีฐานข้อมูลส่วนตัวหรือบริการส่งเอกสารให้อัตโนมัติ

PDF มีสองกรณีที่ควรเข้าใจ

ชนิดวิธีตรวจ
PDF ต้นฉบับที่แนบตอนออกตรวจ Hash ทุกไบต์ได้โดยแนบไฟล์เดิมที่หน้าตรวจสอบ
PDF ที่พิมพ์จากเว็บหลังออกสแกน QR เพื่อตรวจสถานะทะเบียน และใช้ JSON คู่กันเพื่อยืนยันชื่อ/รายละเอียด PDF นี้ไม่ได้มี Hash ผูกไว้กับรายการเดิมโดยอัตโนมัติ

STEP 10 / ไม่ต้องเชื่อม Wallet ก็ตรวจได้

ตรวจใบรับรอง 4 วิธี

วิธี A — ใช้รหัสใบรับรอง

  1. เปิด ตรวจสอบใบรับรอง
  2. กรอกรหัส เช่น ST-2026-0001 แล้วกด ตรวจสอบความถูกต้อง
  3. จะเห็นสถานะ หลักสูตร วันที่ออก Wallet และ Hash จากทะเบียน

วิธีนี้ยืนยันว่ารหัสมีอยู่และมีผลหรือถูกเพิกถอนแล้ว ยังไม่ยืนยันว่าชื่อบนเอกสารตรงกับใบที่ออก เพราะชื่อไม่อยู่บน Blockchain

วิธี B — ใช้ไฟล์ JSON เพื่อยืนยันชื่อและรายละเอียด

  1. กด อัปโหลดไฟล์ใบรับรอง .json
  2. เลือกไฟล์ .skilltrust.json ที่ดาวน์โหลดจากผู้ออก ขนาดไม่เกิน 2 MB
  3. ถ้า Hash ตรง จะเห็นชื่อผู้รับและข้อความว่า Hash ตรงกับหลักฐานที่บันทึก
  4. ถ้ามีการเปลี่ยนชื่อ หลักสูตร วันที่ หรือข้อมูลอื่น จะขึ้นว่า ข้อมูลในไฟล์ไม่ตรงกับหลักฐาน
วิธีสาธิตการจับใบรับรองปลอม
  1. ทำสำเนาไฟล์ JSON เพื่อเก็บต้นฉบับ
  2. เปิดสำเนาด้วย Text Editor เช่น Notepad หรือ VS Code
  3. แก้เฉพาะข้อความ recipientName เป็นชื่ออื่น อย่าลบเครื่องหมายคำพูดหรือจุลภาค
  4. บันทึกเป็น .json แล้วนำเข้าเว็บอีกครั้ง
  5. ระบบต้องแสดงว่า Hash ไม่ตรง ข้อมูลชื่อที่แก้จะไม่ถูกยอมรับ

วิธี C — สแกน QR ด้วยกล้องหรือรูปภาพ

  • กล้อง: กดสแกน QR แล้วอนุญาตกล้อง วาง QR ไว้ในภาพ หากไม่รองรับกล้องใช้วิธีรูปภาพ
  • รูปภาพ: กดรูป QR Code แล้วเลือก PNG ที่ดาวน์โหลดจากหน้ารายละเอียดใบรับรอง
  • โทรศัพท์: ใช้กล้องมือถือสแกน QR บน PDF เพื่อเปิดลิงก์ตรวจสถานะ

QR มีเพียงเลขอ้างอิงหรือ ID และ Address ของทะเบียน ไม่ใส่ชื่อบุคคล QR ยืนยันสถานะทะเบียน ส่วนรายละเอียดให้ใช้ JSON หาก Contract ในลิงก์ไม่ตรงกับเว็บ ระบบจะแจ้งให้ตรวจสอบการตั้งค่า

วิธี D — ตรวจว่า PDF ต้นฉบับถูกแก้ไขหรือไม่

  1. ตรวจรหัสหรือ JSON ของใบที่แนบ PDF ตอนออก
  2. จะมีปุ่ม ตรวจ Hash ของ PDF ต้นฉบับ ใต้ผลตรวจ
  3. เลือก PDF ต้นฉบับเดิม → ขึ้นว่า PDF ตรงกับต้นฉบับที่บันทึกไว้
  4. เลือกไฟล์อื่น หรือไฟล์ที่เปลี่ยนข้อมูล/บันทึกใหม่ → Hash อาจไม่ตรง
Hash ของ PDF เทียบทุกไบต์ แม้หน้าตาเหมือนเดิม แต่มีการ Save ใหม่หรือ metadata เปลี่ยน ก็อาจไม่ตรง ต้องใช้ไฟล์ต้นฉบับที่แนบไว้ตอนออก

อ่านผลตรวจอย่างไร

  • มีผลใช้งาน: พบทะเบียนและยังไม่ถูกเพิกถอน
  • เพิกถอนแล้ว: พบประวัติ แต่ใช้เป็นใบรับรองที่มีผลไม่ได้
  • ไม่พบ: ไม่มีรหัสในทะเบียนที่เชื่อมอยู่ อาจผิดรหัสหรือใช้ Contract คนละแห่ง
  • Hash ไม่ตรง: รายละเอียดในไฟล์ไม่ตรงกับที่ออกไว้
  • คนละ Contract/เครือข่าย: ตรวจให้แน่ใจว่าไม่ได้นำไฟล์ Demo มาตรวจใน Sepolia หรือสลับ Address

STEP 11 / ควบคุมสิทธิ์บน Smart Contract

เพิ่มผู้มีสิทธิ์และดูใบรับรองผู้เรียน

ให้ Wallet อื่นเป็นผู้ออกใบรับรอง

  1. Owner หรือ Admin เชื่อม Wallet ของตน
  2. ไป จัดการระบบ → จัดการสิทธิ์
  3. วาง Wallet Address ของคนที่จะได้รับสิทธิ์
  4. เลือกบทบาท Issuer — ออกใบรับรอง และการดำเนินการ มอบสิทธิ์
  5. กดบันทึกสิทธิ์และยืนยัน MetaMask
  6. ผู้ได้รับสิทธิ์เปิดเว็บไซต์เดียวกัน ตั้ง Contract เดียวกัน และเชื่อม Wallet ของตัวเอง จะออกใบรับรองได้ แต่เพิกถอนไม่ได้
  7. หากต้องการถอนสิทธิ์ ใช้ Address เดิม เลือก Issuer และ ถอนสิทธิ์ แล้วบันทึก

Administrator: จัดการหลักสูตร ออก/เพิกถอน และจัดการ Issuer ได้ การเพิ่มหรือถอน Admin ทำได้โดย Owner เท่านั้น Owner เริ่มต้นถอดออกไม่ได้และโค้ดนี้ไม่มีฟังก์ชันโอน Owner

ให้ผู้เรียนดู Dashboard ของตน

  1. ผู้เรียนเปิดเว็บไซต์ กดเชื่อมต่อ Wallet แล้วเลือกบัญชีที่ได้รับใบรับรอง
  2. เข้า ใบรับรองของฉัน ระบบอ่านรายการจาก Wallet Address นั้น
  3. หากเห็นเฉพาะ Address แทนชื่อ ให้นำเข้า JSON ที่ผู้ออกส่งให้ในหน้าตรวจสอบ แล้วกลับมาดูอีกครั้ง
  4. ใบรับรองที่เพิกถอนแล้วยังแสดงในประวัติพร้อมสถานะ
หากเปลี่ยนบัญชีหรือเครือข่ายใน MetaMask เว็บไซต์จะยกเลิกการเชื่อมต่อ ให้กดเชื่อมต่อ Wallet อีกครั้งเพื่ออ่านสิทธิ์และประวัติของบัญชีใหม่

STEP 12 / ใช้ Admin เท่านั้น

เพิกถอนใบรับรองโดยเก็บประวัติ

  1. เชื่อม Wallet ที่เป็น Owner หรือ Admin
  2. ไป จัดการระบบ → ทะเบียนใบรับรอง
  3. หาใบที่ต้องการ แล้วกดไอคอนเพิกถอนรูปโล่ด้านขวาของแถว
  4. ตรวจรหัสในหน้าต่างยืนยันให้ถูกต้อง แล้วกด ยืนยันเพิกถอน
  5. ยืนยันธุรกรรมใน MetaMask และรอสำเร็จ
  6. เปิดหน้าตรวจสอบรหัสเดิมอีกครั้ง ต้องเห็น ใบรับรองถูกเพิกถอนแล้ว และวันที่เพิกถอน
เพิกถอนแล้วย้อนกลับไม่ได้ รหัสเดิมถูกสงวนไว้ตลอด หากต้องออกใหม่ให้ใช้รหัสใหม่ ข้อมูลเดิมและ Hash ยังคงอยู่เพื่อให้ตรวจประวัติได้

STEP 13 / เว็บไซต์ static + Smart Contract backend

GitHub Pages และการแก้ไขเว็บในอนาคต

โค้ดอยู่ใน repository srwjd/Blockchain-Digital-Certificate-Verification-System เมื่อแก้ไฟล์และ commit ไป branch main ระบบจะทดสอบและ deploy ใหม่อัตโนมัติ

ตรวจหรือเปิดการตั้งค่า Pages

  1. เปิด repository → Settings → เมนู Pages
  2. ตรง Build and deployment เลือก Source เป็น GitHub Actions
  3. เปิดแท็บ Actions ของ repository
  4. เลือก workflow Test and deploy GitHub Pages
  5. ดู run ล่าสุด ต้องผ่าน job build และ deploy
  6. หากต้องการสั่งใหม่ กด Run workflow เลือก main แล้ว Run
  7. เมื่อผ่าน เปิด URL ของเว็บไซต์แล้วรีเฟรช

ถ้าต้องการรันหรือแก้โค้ดบนเครื่องตัวเอง

ติดตั้ง Node.js เวอร์ชัน 22 ขึ้นไปและ Git เปิด Terminal แล้วใช้:

git clone https://github.com/srwjd/Blockchain-Digital-Certificate-Verification-System.git
cd Blockchain-Digital-Certificate-Verification-System
npm ci
npm run dev

เปิด URL ที่ Terminal แสดง เมื่อแก้เสร็จ ตรวจด้วย:

npm run check

GitHub Pages เก็บเว็บอย่างเดียว ไม่รัน Express/Node server หลังบ้านของโครงการนี้จึงเป็น Smart Contract บน Sepolia การ deploy เว็บกับการ deploy Contract เป็นคนละขั้นตอน

STEP 14 / ตัวอย่างลำดับสาธิต

เช็กลิสต์ส่งงานครบตามโจทย์

  1. แสดงหน้า Dashboard และอธิบายว่าเป็น Demo หรือ Sepolia
  2. แสดง Smart Contract ใน Remix และ Address ที่ deploy
  3. เชื่อม Wallet ผู้ดูแลแล้วสร้างหลักสูตรใหม่
  4. ออกใบรับรองให้ Wallet ผู้เรียน แนบ PDF ตัวอย่างก่อนออกถ้าต้องการสาธิตการตรวจ PDF
  5. ดาวน์โหลด JSON และพิมพ์เป็น PDF พร้อม QR
  6. ลองออกเลขเดิมอีกครั้ง ระบบต้องปฏิเสธ
  7. ตรวจด้วยรหัส ต้องพบรายการและมีผลใช้งาน
  8. นำเข้า JSON ต้นฉบับ ต้องแสดงชื่อและ Hash ตรง
  9. เปลี่ยนชื่อใน JSON สำเนา แล้วนำเข้าอีกครั้ง ต้องตรวจพบการแก้ไข
  10. สแกนหรืออัปโหลดภาพ QR ต้องเปิดผลตรวจสถานะได้
  11. ใช้ PDF ต้นฉบับตรวจ แล้วใช้ไฟล์อื่นตรวจ เพื่อแสดงผลตรง/ไม่ตรง
  12. เชื่อม Wallet ผู้รับ ดูรายการในใบรับรองของฉัน
  13. สลับ Wallet ที่ไม่มีสิทธิ์ แสดงว่าออก/เพิกถอนไม่ได้
  14. Owner ให้ Issuer แล้วแสดงว่าออกได้แต่เพิกถอนไม่ได้
  15. กลับ Admin เพิกถอนใบหนึ่ง ตรวจรหัสเดิมอีกครั้ง ต้องเห็นประวัติและสถานะเพิกถอน

ถ้ายังไม่มี Sepolia ETH ใช้ Demo สาธิต UI และ Hash ได้ แต่ต้องอธิบายให้ชัดว่ายังไม่ใช่ธุรกรรมจริง หากต้องแสดงหลักฐาน Blockchain ให้ทำบน Sepolia และเปิด Etherscan ของ contract ประกอบ

STEP 15 / แก้ปัญหาด้วยตัวเอง

ปัญหาที่พบบ่อย

อาการให้ตรวจหรือทำสิ่งนี้
กด Wallet แล้วไม่เปิด MetaMaskดูว่าอยู่ Demo หรือไม่ Demo ใช้บัญชีจำลอง ถ้า Sepolia ให้ติดตั้งส่วนขยายในเบราว์เซอร์เดียวกัน หรือเปิดผ่าน Wallet browser
Remix ไม่มี Injected Providerตรวจว่าติดตั้ง/ปลดล็อก MetaMask แล้ว รีเฟรช Remix หรือดูตัวเลือก Browser Extension / MetaMask ใน Environment
Insufficient funds / Gas ไม่พอขอ Sepolia ETH ให้ Wallet ที่ใช้ deploy/ส่งธุรกรรม ตรวจว่าไม่ได้อยู่ Mainnet
Invalid opcode ตอน deployกลับ Compiler ตั้ง EVM Version เป็น shanghai, optimizer 200 แล้ว compile ใหม่ ตรวจ network ก่อน deploy อีกครั้ง
ไม่พบ Smart Contract ที่ Address นี้ใช้ Contract Address จาก Deployed Contracts ไม่ใช่ Wallet Address และอย่าใช้ Address จาก Remix VM
Unauthorized / ไม่มีสิทธิ์ใช้ Wallet ผู้ deploy หรือให้ Owner มอบสิทธิ์ Admin/Issuer ให้ Address นั้น Contract บังคับสิทธิ์จริง
เห็น Viewer ทั้งที่เป็น Ownerตรวจบัญชี MetaMask, Contract Address และ network แล้วเชื่อม Wallet ใหม่
AlreadyExists / รหัสถูกใช้แล้วเปลี่ยนเป็นรหัสใหม่ เพิกถอนหรือลบข้อมูลใน browser ก็ไม่ทำให้ใช้รหัสเดิมบน Blockchain ซ้ำได้
ไม่เห็นชื่อในอีกเครื่องชื่อไม่ได้อยู่บน Blockchain ให้นำเข้า JSON ต้นฉบับจากผู้ออกที่หน้าตรวจสอบ
JSON คนละ Contractตรวจว่าไฟล์เป็น Demo หรือ Sepolia และ Address ตรงกับที่ตั้งค่าไว้
เพื่อนเปิดเว็บแล้วยังเป็น Demoแก้ public/config.json บน GitHub เป็น Sepolia พร้อม Address จริง แล้วรอ Actions ผ่าน ดูข้อ 7
เปลี่ยน config กลางแต่เครื่องเดิมไม่เปลี่ยนค่าที่เคยบันทึกในหน้า Settings มีลำดับก่อน config กลาง ให้ตั้งค่าในหน้า Settings อีกครั้ง หรือเปิด Incognito
PDF หน้าตาเหมือนเดิมแต่ Hash ไม่ตรงการ Save ใหม่อาจเปลี่ยน metadata ใช้ไฟล์ต้นฉบับที่แนบตอนออก ไม่ใช้ไฟล์พิมพ์ใหม่จากหน้าเว็บแทน
ปุ่มตรวจ PDF ไม่แสดงใบนี้ไม่ได้แนบ PDF ตอนออก ถ้าต้องการ Hash ของ PDF ต้องใช้รหัสใหม่แล้วแนบก่อนออก
กล้องไม่ทำงานอนุญาต Camera ใน browser และใช้ HTTPS ถ้าไม่รองรับให้เลือกอัปโหลดรูป QR
RPC ล่ม/ช้า/ถูกจำกัดลองใหม่หรือใช้ HTTPS Sepolia RPC ที่รองรับ CORS และไม่ต้องเปิดเผย key ลับ
เว็บ 404 หลัง pushตรวจ Pages → Source = GitHub Actions, run ล่าสุดต้องผ่าน และเปิด URL ที่มีชื่อ repository ครบ
MetaMask ยกเลิกธุรกรรมยังไม่มีการเปลี่ยนข้อมูล ให้ตรวจรายละเอียดแล้วลองส่งใหม่เมื่อพร้อม

STEP 16 / อธิบายตอนนำเสนอ

ข้อมูลใดอยู่บน Blockchain

หลักสูตร, ID ที่คำนวณจากเลขอ้างอิง, Hash ของข้อมูลใบรับรอง, Hash ของ PDF ถ้ามี, Wallet ผู้รับ/ผู้ออก และเวลาออก/เพิกถอน ไม่มีชื่อผู้เรียนหรือไฟล์เอกสารฉบับเต็ม Wallet บนเครือข่ายยังเป็นข้อมูลสาธารณะที่อาจเชื่อมโยงกับบุคคลได้

ทำไมเปลี่ยนชื่อแล้วตรวจพบได้

ข้อมูล + nonce → จัดเรียง JSON แบบเดียวกัน → SHA-256 → เก็บ Hash บน Blockchain
ตอนตรวจไฟล์ คำนวณซ้ำแล้วเปรียบเทียบ ถ้าแก้ข้อมูล Hash จะเปลี่ยน

Nonce คือข้อมูลสุ่ม 32 bytes ที่รวมใน JSON ทำให้ข้อมูลส่วนบุคคลชุดเดียวกันไม่ได้ Hash เดิมทุกครั้ง ต้องเก็บไฟล์นี้ให้ครบ ชุดทดสอบตรวจทั้งชื่อ หลักสูตร วันที่ Wallet document hash และ nonce

ข้อจำกัดที่ควรอธิบายตามจริง

  • เป็นโครงการสาธิตการศึกษา ใช้เครือข่ายทดสอบ Sepolia ยังไม่มี security audit สำหรับงาน production
  • ไม่มี private database หรือระบบจัดส่งเอกสารอัตโนมัติ JSON ต้องสำรองและส่งให้ผู้รับเอง
  • Hash ยืนยันว่าเอกสารตรงกับที่ผู้ออกลงทะเบียน ไม่ยืนยันว่าผู้รับเรียนผ่านจริง หากผู้ออกลงข้อมูลผิดต้องเพิกถอนและออกใหม่
  • Wallet connection ใช้แทนสิทธิ์ผู้ดูแล ไม่มีระบบ username/password; ผู้ไม่มีสิทธิ์เรียกฟังก์ชันเขียนโดยตรงก็ถูก contract ปฏิเสธ
  • หน้า Overview และทะเบียนโหมดจริงแสดงใบล่าสุดไม่เกิน 50 ใบ ค้นหารายการเก่าด้วยรหัสหรือ JSON ได้ ส่วนประวัติ Wallet อ่านแบบแบ่งหน้า
